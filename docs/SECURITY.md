# Безопасность

Документ описывает модель угроз, реализованные меры защиты, осознанно
принятые риски и порядок ответственного разглашения уязвимостей.

## Что защищено

### Контроль доступа

- **RLS включён на всех таблицах в `public`.** Дефолт — «запрещено»,
  политики выдают доступ явно.
- **Роли — через отдельную таблицу.** `user_roles` + SECURITY DEFINER
  функция `has_role()` исключают privilege escalation и рекурсию в RLS.
- **`SECURITY DEFINER` функции изолированы.** `EXECUTE` отозван у `anon`
  и `authenticated`; функции вызываются только из RLS-политик и edge-функций.

### Edge-функции

- **CORS** настроен явно, не `*` для авторизованных эндпоинтов.
- **Валидация входа** через Zod (или ручная для простых случаев).
- **Service role key** только в edge — никогда не уходит в клиент.
- **Ответы не содержат чувствительных полей** — например, `get-test-questions`
  скрывает `correct_index` и `expected_answer`.

### Хранилище

- **`rrweb-sessions` — приватный.** Доступ к записям только через signed
  URL с коротким TTL, выдаваемый `replay-signed-url`.
- **`test-attachments` — публичный**, но без `LIST` через RLS — нельзя
  перебрать содержимое бакета. Файлы доступны только по точному пути.

### Аутентификация

- **HIBP включён** — пароли проверяются по базе утечек.
- **HMAC-токен учителя** — подписан `TEACHER_JWT_SECRET`, TTL ~12 часов,
  верификация в `_shared/teacher-auth.ts`.
- **Анонимные signups отключены** в Supabase Auth.

### Защита ученика от себя

См. [TESTING_FLOW.md → Античит](./TESTING_FLOW.md#античит).

## Осознанно принятые риски

### Анонимный поток ученика

Ученик идентифицируется только по ФИО + классу. Возможны:

- **Подмена имени** — ученик может написать чужое ФИО. Митигация: античит
  логирует поведение, учитель сверяет результаты.
- **Множественные попытки** — частично детектируются `student_fingerprint`
  (browser fingerprint в `test_attempts`).

Принято потому, что регистрация всех учеников создаёт сильное трение и
неприемлема для целевой аудитории (школьники).

### Публичный bucket `test-attachments`

Файлы доступны по прямой ссылке без авторизации. Это нужно, чтобы учитель
мог быстро открыть фото из Telegram-уведомления. Митигация: имена файлов
содержат UUID, перебор практически нереален.

### `verify_jwt = false` у большинства edge-функций

Объяснено в [EDGE_FUNCTIONS.md](./EDGE_FUNCTIONS.md). JWT валидируется
в коде функции, где это нужно. Анонимные функции защищены валидацией
входа.

## Что НЕ должно происходить (инварианты)

Эти инварианты должны соблюдаться при любых будущих изменениях:

1. Ученик **никогда** не должен получать `correct_index` / `expected_answer`
   до сдачи теста.
2. Ученик **никогда** не должен иметь возможность вставить запись в
   `test_results` напрямую — только через `send-test-results`.
3. Service role key **никогда** не должен попадать в клиентский код или
   ответы edge-функций.
4. Роли **никогда** не должны храниться вне `user_roles`.
5. Прямой клиентский доступ к `student_drafts` (INSERT/UPDATE/DELETE)
   **должен** оставаться закрытым — все операции через edge.

## Регулярные проверки

```sh
# Линтер схемы и RLS (Supabase)
supabase db lint  # или через MCP supabase--linter

# Зависимости (npm audit)
npm audit
```

Перед каждым релизом:

1. Прогнать `supabase--linter` — должно быть 0 warnings.
2. Прогнать security scan — закрыть все critical/high.
3. Проверить, что не появилось новых таблиц без RLS.
4. Проверить, что новые edge-функции валидируют вход.

## Data Retention

Edge function `cleanup-old-data` (вызывается вручную или внешним cron-ом
с учительским HMAC-токеном) удаляет:

- `student_drafts` старше **30 дней** — черновики уже неактуальны.
- `auth_attempts` старше **7 дней** — лог брутфорс-попыток.
- Объекты в bucket `rrweb-sessions` старше **90 дней** — записи сессий.

Сами `test_attempts` и `test_results` сохраняются бессрочно (история оценок).

## Защита учительского входа

- Пароль хранится как **bcrypt-хэш** (cost 10) в `teacher_credentials`.
- `TEACHER_PASSWORD` в env используется только для one-time bootstrap при
  первом успешном логине. После него env-секрет можно удалить.
- **Anti-brute-force:** ≥5 неудачных попыток за 15 минут с того же IP+login
  → ответ `429 Too Many Requests` с `Retry-After: 900`. Все попытки логируются
  в `auth_attempts`.
- Токен — HMAC-SHA256 на 8 часов; payload включает `iat` для будущей ротации.

## CSP

Заголовок `Content-Security-Policy` задан в `public/_headers` (Cloudflare Pages)
и в `netlify.toml` (Netlify). `'unsafe-inline'` и `'unsafe-eval'` оставлены
из-за ограничений Vite/shadcn — переход на nonce-режим запланирован отдельно.

и не публикуйте детали до выхода патча. Спасибо.
