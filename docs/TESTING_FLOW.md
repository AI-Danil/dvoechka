# Поток прохождения теста

## Два режима

### Обычный режим (анонимный)

Ученик заходит на `/`, выбирает класс → предмет → тест, вводит ФИО,
проходит. Никакой регистрации.

### Live-режим

Учитель создаёт сессию (`/teacher/live`), получает PIN-код. Ученики заходят
на `/live`, вводят код и ФИО — все попадают в один «зал ожидания». Когда
учитель нажимает «Старт», у всех одновременно стартует общий таймер
(серверный `ends_at`).

## Структура теста

Тест состоит из двух частей:

1. **Квиз** — компонент `Quiz.tsx`. Один вопрос на экране, поквопросный
   таймер (`time_per_question_sec`), нельзя вернуться назад.
2. **Письменная часть** — компонент конкретного теста из `src/components/tests/`
   (например, `Grade8Physics.tsx`). Можно прикреплять фото/файлы.

Какой именно письменный компонент рендерить — определяется по
`(grade, subject, kind)` в реестре `src/lib/quizRegistry.ts`.

## Валидация имени

Жёсткое правило: **ровно 2 русских слова**.

```text
"Иванов Иван"        ✓
"Иванов Иван 2"      ✓ (третье слово — цифра → скрытая попытка пересдачи)
"Ivan Ivanov"        ✗ (латиница)
"Иванов"             ✗ (одно слово)
"Иванов Иван Петров" ✗ (три слова без цифры)
```

Цифра в третьем слове — недокументированная для ученика возможность
пересдать тест: `attempt = N` пишется в `test_results`, и учитель видит
все попытки.

Реализация — `src/lib/strictRules.ts`.

## Автосохранение (3 уровня)

### 1. localStorage — мгновенно

`Quiz.tsx` сохраняет состояние при каждом ответе и каждую секунду
тика таймера. Ключ — `quiz_<grade>_<subject>_<testId>_<attempt>`.
Письменная часть в `Index.tsx` сохраняется на каждое изменение поля.

### 2. Серверный draft — раз в 5 секунд (обычный режим)

Edge-функция `save-draft` записывает полный снимок (квиз + письменная
часть) в `student_drafts`. Дебаунс — 5 сек, дедупликация по hash полезной
нагрузки.

При возврате к тесту вызывается `load-draft`. Если на сервере есть более
свежий снимок — восстанавливается с тостом «☁️ Черновик восстановлен с
сервера».

При сабмите вызывается `clear-draft`.

Beacon-флэш на `pagehide` / `beforeunload` / `visibilitychange (hidden)`
через `navigator.sendBeacon` — успевает отправить даже при закрытии вкладки.

### 3. Серверный progress — live-режим

В live-режиме каждый ответ синхронизируется с `test_attempts.draft_answers`
через `save-attempt-progress`. Это позволяет учителю видеть, кто на каком
вопросе сейчас.

## Античит

Активная защита (UI блокируется):

- **Копирование/вставка/вырезание** в области ответов — событие
  `copy/paste/cut` подавляется + `notify-copy-attempt` (Telegram).
- **Контекстное меню** (правый клик) — заблокировано.
- **DevTools** — `useDevToolsBlock` детектирует открытие, показывает
  заглушку и шлёт алерт.
- **Drag-and-drop** текста и файлов в неподходящие зоны — блокируется.

Пассивный мониторинг (молча пишется в `cheat_log`):

- **Видимость вкладки** — `visibilitychange`, переключения считаются.
- **Потеря фокуса** окна.
- **Полный экран** — выход из.
- **Resize** окна (детектирует попытку вынести вкладку в side-by-side).

Реализация: `src/hooks/useAntiCheatNotify.ts`. Логирование в результатах:
`test_results.cheat_log` (jsonb массив событий).

## Запись экрана

`useRrwebRecorder` записывает DOM-события через rrweb, чанками отправляет
в `rrweb-sessions` (приватный bucket). После сабмита путь к записи
сохраняется в `test_results.replay_url` через `update-replay-url`.

Учитель смотрит запись через `/replay/:resultId` — фронт запрашивает
signed URL у `replay-signed-url` (TTL ~1 час) и проигрывает в плеере.

## Прикрепление файлов

Файлы (фото решения, scan тетради) загружаются в публичный bucket
`test-attachments`. Перед загрузкой имя санитизируется в ASCII
(`src/components/FileAttach.tsx`) — иначе Supabase Storage возвращает
ошибку на кириллицу в пути.

После сабмита прямые публичные URL пишутся в `test_results.attachments`
(jsonb).

## Финальная отправка

`send-test-results` (edge):

1. Валидирует payload (Zod).
2. Считает баллы за квиз (сравнение с `correct_index`).
3. Делает INSERT в `test_results` (service role).
4. Формирует Telegram-отчёт: ФИО, класс, предмет, баллы, прикрепления,
   античит-сводка, ссылка на запись.
5. Отправляет в Telegram (длинные сообщения разбиваются на части).
6. Возвращает `{ id, score }` фронту.

Фронт показывает экран успеха со счётом и зачищает все локальные данные
+ серверный draft.
