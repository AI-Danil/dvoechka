# Архитектура

## Общая схема

```text
┌──────────────────────────────────────────────────────────────┐
│  Браузер ученика / учителя                                    │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ React SPA (Vite, TypeScript)                            │  │
│  │  • React Router (страницы)                              │  │
│  │  • TanStack Query (серверное состояние)                 │  │
│  │  • shadcn/ui + Tailwind (визуал)                        │  │
│  │  • rrweb (запись экрана)                                │  │
│  └─────────────────┬──────────────────────────┬────────────┘  │
└────────────────────┼──────────────────────────┼───────────────┘
                     │ HTTPS                    │ HTTPS
                     ▼                          ▼
       ┌─────────────────────────┐   ┌──────────────────────┐
       │ Supabase REST / RPC     │   │ Supabase Edge Funcs  │
       │ (PostgREST + RLS)       │   │ (Deno, serverless)   │
       └────────────┬────────────┘   └──────────┬───────────┘
                    │                            │
                    ▼                            ▼
       ┌─────────────────────────────────────────────────────┐
       │ PostgreSQL                                           │
       │  • tests, test_questions, test_results               │
       │  • test_attempts, test_sessions, ...                 │
       │  • user_roles (admin / teacher / student)            │
       │  • RLS-политики на всех таблицах                     │
       └─────────────────────────────────────────────────────┘
                    │
                    ▼
       ┌─────────────────────────┐   ┌──────────────────────┐
       │ Supabase Storage        │   │ Telegram Bot API     │
       │  • test-attachments     │   │  (через edge func)   │
       │  • rrweb-sessions       │   └──────────────────────┘
       └─────────────────────────┘
```

## Принципы

1. **Тонкий клиент, жирный backend.** Любая операция, требующая доверия
   (запись результата, создание сессии, выдача подписанной ссылки), идёт
   через edge-функцию с валидацией. Прямой клиентский insert в `test_results`
   запрещён политиками RLS.

2. **Row-Level Security везде.** Все таблицы в `public` имеют включённый RLS
   и явные политики. Дефолт — «запрещено». Никаких `USING (true)` без
   объяснения в `DATABASE.md`.

3. **Роли через отдельную таблицу.** `user_roles` + SECURITY DEFINER функция
   `has_role(uid, role)` — чтобы избежать рекурсии в RLS и privilege
   escalation через UPDATE на собственную строку.

4. **Анонимный поток для учеников.** Ученик не регистрируется — вводит ФИО
   и сразу проходит тест. Идентификация по `(student_name, grade, subject,
   test_id, attempt)`. Античит и автосейв работают на этом ключе.

5. **Учитель — отдельная авторизация.** Помимо Supabase Auth есть HMAC-токен
   с коротким TTL для legacy-страниц учителя (см. AUTH_AND_ROLES.md).

6. **Multi-mirror деплой.** Один backend, несколько фронтов на разных
   доменах. Это нужно из-за региональных блокировок: ученик может зайти
   с Lovable, Netlify, Cloudflare Pages или GitHub Pages — данные пишутся
   в одну БД.

## Поток прохождения теста (упрощённо)

```text
Ученик → /                            (выбор класса/предмета/теста)
       → /test/...                    (тест: квиз + письменная часть)
         │
         ├─ каждые 5 сек:  edge:save-draft  → student_drafts (jsonb)
         ├─ при копировании: edge:notify-copy-attempt → Telegram
         │
       → submit                       
         ├─ edge:send-test-results    → test_results + Telegram отчёт
         └─ edge:clear-draft          → удаляет черновик
```

Подробнее — `TESTING_FLOW.md`.

## Live-сессии

Учитель создаёт «сессию» с кодом-PIN, ученики присоединяются по коду. Сессия
имеет общий серверный таймер (`ends_at`), все участники видят одинаковый
обратный отсчёт. Прогресс ученика пишется в `test_attempts.draft_answers`.

## Запись экрана

Используется [rrweb](https://www.rrweb.io/) — лёгкий рекордер DOM-событий.
Запись складывается в приватный bucket `rrweb-sessions`, ссылка для просмотра
выдаётся учителю через `replay-signed-url` (signed URL, TTL ~1 час).

## Античит

Ловятся: copy/paste/cut, переключение вкладки, попытки открыть DevTools,
правый клик, drag-and-drop. Все события пишутся локально в `cheat_log`,
самые важные (копирование, выход с вкладки) — мгновенно отправляются в
Telegram через `notify-copy-attempt`.
