## Проблема

У некоторых учеников в разных браузерах открывается белый экран. Адрес правильный, но React ничего не рендерит. В коде нашёл несколько причин, почему это может происходить:

### Причины «белого экрана»

1. **Нет ErrorBoundary.** Любая ошибка при рендере любого компонента (например, в `Index.tsx`, в `Quiz`, в одном из `Grade*` тестов) полностью ломает UI — React размонтирует всё дерево, остаётся пустой `<div id="root">`. Сейчас в проекте нет ни одного `ErrorBoundary`.
2. **Нет глобального `window.onerror` / `unhandledrejection`.** Ошибки в асинхронном коде (Supabase запросы, edge-функции) тоже могут приводить к падениям без логов.
3. **`supabase` клиент жёстко использует `localStorage`** (`src/integrations/supabase/client.ts`). В Safari Private Mode, в Яндекс.Браузере с заблокированными cookies, во встроенных WebView (VK, Telegram) обращение к `localStorage` может бросить `SecurityError` ещё до того, как отрисуется хоть что-то — экран остаётся белым.
4. **`rrweb` рекордер** (`useRrwebRecorder`) и `CompressionStream` могут падать в старых мобильных браузерах. Сейчас ошибка перехватывается частично, но если `rrwebRecord(...)` бросит синхронно — упадёт весь компонент.
5. **`useDevToolsBlock` + контекстное меню**: на iOS/Android из-за разной семантики событий выглядит безопасно, но любая ошибка внутри `notify()` уронит дерево.

## Что делаю

### 1. Глобальный ErrorBoundary
Создаю `src/components/ErrorBoundary.tsx` — класс-компонент, который ловит ошибки рендера и показывает понятный экран:
- «Что-то пошло не так. Обновите страницу» + кнопка «Перезагрузить»
- Текст ошибки (свернуть/развернуть) — чтобы ученик мог скинуть скрин учителю
- Лог в консоль и (если возможно) отправка в edge-функцию `log-cheat-event` с типом `client_crash` — учитель сразу увидит, что у ученика упало.

Оборачиваю весь `<App />` в `main.tsx`, плюс отдельный ErrorBoundary вокруг `<Routes>` в `App.tsx`, чтобы падение одной страницы не уносило всё.

### 2. Глобальные обработчики ошибок
В `main.tsx` добавляю:
```ts
window.addEventListener("error", ...)
window.addEventListener("unhandledrejection", ...)
```
Они логируют ошибку в консоль и в edge-функцию (best-effort, без await), не давая упасть приложению.

### 3. Безопасный storage для Supabase
**НЕ редактирую** `src/integrations/supabase/client.ts` (он автогенерируется). Вместо этого добавляю `try/catch`-полифилл `localStorage` в `main.tsx` ДО импорта `App`:
```ts
try { window.localStorage.setItem("__t","1"); window.localStorage.removeItem("__t"); }
catch { /* подменяем на in-memory storage */ }
```
Это решает проблему Safari Private / заблокированных cookies — `supabase-js` перестаёт падать на инициализации.

### 4. Защита rrweb
В `useRrwebRecorder` оборачиваю сам вызов `rrwebRecord({...})` в `try/catch` — если рекордер не стартует (старый браузер), тест всё равно работает, просто без записи.

### 5. Простая страница-фолбэк в `index.html`
Добавляю в `<div id="root">` минимальный inline-fallback («Загружаем…»), чтобы при медленном JS ученик видел хоть что-то, а не пустой белый экран.

## Что НЕ трогаю

- Не меняю `src/integrations/supabase/client.ts` и `types.ts` (запрещено).
- Не меняю логику тестов, сессий, антитчита.
- Не делаю миграций БД.

## Технические файлы

- `src/components/ErrorBoundary.tsx` — новый
- `src/main.tsx` — обернуть App, добавить глобальные обработчики и localStorage-shim
- `src/App.tsx` — внутренний ErrorBoundary вокруг Routes
- `src/hooks/useRrwebRecorder.ts` — try/catch вокруг старта рекордера
- `index.html` — inline-fallback в `#root`

После внедрения «белый экран» либо исчезнет, либо превратится в понятный экран ошибки с текстом, который ученик сможет переслать.
