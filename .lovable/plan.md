# План

## 1. База данных (миграция)
Добавляю минимум для Варианта A, но **без поломки текущего флоу ученика**:
- `subjects(id, name)` — предметы
- `classes(id, name, year)` — классы (7А, 8Б…)
- `teachers(id, user_id → auth.users, full_name, email)` — профили учителей
- `students(id, full_name, class_id, user_id nullable)` — ученики; `user_id` пока **nullable**, чтобы сохранить безпарольный флоу
- `teacher_assignments(teacher_id, class_id, subject_id)` — кто что преподаёт
- RLS на все таблицы: admin видит всё, teacher — только свои назначения, student/anon — закрыто
- Сидим базовые данные: предметы (Информатика, Физика, Технология), классы (7А, 8А, 9А)

Старая таблица `test_results` **не трогается** — продолжает принимать `student_name` строкой через edge-функцию `send-test-results`. Привязку к `students.id` добавим позже, когда переведём учеников на логины.

## 2. Auth + первичная настройка
- Включу email/password auth, **без подтверждения email** (для удобства теста — потом включим обратно).
- Страница `/auth` — логин и регистрация (email+пароль).
- На странице `/auth` кнопка-сидер «Создать тестового учителя Teatcher01@test.ru» — видна только если в системе нет учителей. Создаёт через edge-функцию `seed-teacher` с service-role.
- После первой регистрации в админке кнопка «Стать админом» — доступна только если в системе нет админов.

## 3. Дашборды
- `/admin/dashboard` (роль admin) — счётчики (учителей N, классов N, тестов N, результатов N), список учителей, кнопка «Пригласить учителя» (заглушка пока), кнопка «Управление ролями».
- `/teacher/dashboard` (роль teacher) — мои предметы, мои классы, последние результаты моих учеников (через `list-results` с фильтром).
- `/student/dashboard` (роль student) — пока пусто, заглушка «доступные тесты», т.к. учеников без логина ещё не переводим.
- Старый `/admin` оставляю как `/admin/results` — общий список результатов.
- Маршрутизация: после логина по роли редиректим в нужный дашборд. Если ролей несколько — показать выбор.

## 4. Защита маршрутов
- Хук `useAuth()` — текущий user + роли.
- Компонент `<RequireRole role="admin|teacher">` — обёртка для приватных страниц.
- Страница ученика `/` (где сейчас `Index.tsx`) **остаётся публичной** — без логина, как сейчас.

## 5. Что НЕ делаю в этот заход
- Конструктор тестов (отдельная большая задача).
- Назначения тестов классам (`test_assignments`).
- Перевод учеников на логины.
- Удаление старого `TeacherLoginGate` (HMAC) — оставлю работать параллельно для существующего `/admin`, чтобы ничего не сломать. После того как новая система обкатается — уберём.

## Технические детали
- Edge-функция `seed-teacher`: создаёт `auth.users` через `admin.createUser({email, password, email_confirm:true})`, добавляет в `user_roles` роль `teacher`, в `teachers` профиль. Защита: возвращает 403, если в системе уже есть хоть один teacher.
- Edge-функция `claim-admin`: вызывается залогиненным юзером, добавляет ему роль `admin` если в системе нет ни одного админа.
- `verify_jwt = false` для `seed-teacher`, `true` для `claim-admin`.
- Все RLS на новые таблицы — через `has_role()`.
- Не трогаю `test_results`, `send-test-results`, `list-results`, `TeacherLoginGate` — старый флоу работает параллельно.

После реализации:
1. Открываешь `/auth` → видишь кнопку «Создать тестового учителя» → нажимаешь → создаётся `Teatcher01@test.ru`/`Teatcher01`.
2. Регистрируешься со своим email → нажимаешь «Стать админом» → у тебя роль admin.
3. Логинишься как учитель → попадаешь в `/teacher/dashboard`.
4. Логинишься как админ → попадаешь в `/admin/dashboard`.
5. Ученики продолжают заходить на `/` без логина и писать тесты — ничего не сломалось.
