

## Чиню три проблемы разом

### 1. Лог событий показывает `[object Object]`
**Где:** `src/pages/Replay.tsx`, функция `parseCheatLog`.

**Причина:** для DB-тестов `cheat_log` — это **массив объектов** (`{type, ts, detail}`), а не массив строк. `parseCheatLog` делает `String(line)` → получается `"[object Object]"`. Для старых хардкод-тестов лог был массивом строк типа `"[12:34:56] copy"` — там работало.

**Фикс:** научить `parseCheatLog` принимать оба формата. Если элемент — объект, формирую читаемую строку: время из `ts`, тип через словарь (`copy → 📋 Копирование`, `paste → 📥 Вставка`, `blur → 👁 Уход с вкладки` и т.д. — словарь уже есть в `TestResultsList.tsx`, переиспользую).

---

### 2. Админ не видит «Live-сессии» в дашборде
**Где:** `src/pages/AdminDashboard.tsx`.

**Причина:** ссылка «Live-сессии» добавлена только в **`TeacherDashboard.tsx`**. Админ заходит в `AdminDashboard.tsx`, где такой кнопки просто нет. Маршрут `/teacher/live` защищён `RequireRole role="teacher"` → если у админа нет роли `teacher`, он туда не попадёт даже по прямой ссылке.

**Фикс:**
- Добавить в шапку `AdminDashboard.tsx` кнопку «🎙 Live-сессии» → ведёт на `/teacher/live`.
- В `App.tsx` ослабить охрану маршрута: `RequireRole roles={["teacher","admin"]}` (или сделать новый компонент-обёртку) — чтобы админ тоже мог туда зайти.
- В `TeacherLive.tsx` поправить загрузку тестов: сейчас `eq("author_user_id", user.id)` — админ увидит только то, что создал сам. Для админа уберу этот фильтр (покажу все опубликованные тесты).

---

### 3. Нельзя задать время на квиз-вопрос для уже созданного теста
**Где:** дашборд → список «Мои тесты» → кнопка редактирования.

**Причина:** `CreateTestForm` принимает `seconds` только при **первичной генерации**. После создания — изменить нельзя. В `TestPreview` (форма редактирования) поля «время на вопрос» нет.

**Фикс:**
- Добавить в `TestPreview` поле «Время на вопрос (сек)» (5–300), которое читает/пишет `tests.time_per_question_sec`.
- Дополнительно: возле каждого квиз-вопроса показать поле `seconds_override` (необязательное) — это позволит точечно менять время на отдельный вопрос (модель уже поддерживает, бэкенд тоже).
- Сохранение — обычным `UPDATE` через клиент Supabase (RLS на `tests` уже разрешает автору правку) либо через доработку `publish-test` / новый edge — но проще через прямой `update` от автора.
