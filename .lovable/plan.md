
## Починю это точечно: проблема не во фронте, а в самой public view

Причина наконец ясна.

Сейчас `src/lib/dbTests.ts` уже делает правильный запрос:
- читает `public_tests`
- фильтрует по `class_year = 2025`
- фильтрует по `subject_name = "Технология"`
- фильтрует по `class_name like '9%'`

Но сама view `public.public_tests` создана так:

```sql
CREATE VIEW public.public_tests
WITH (security_invoker = true) AS
SELECT ...
FROM public.tests t
JOIN public.classes c ON c.id = t.class_id
JOIN public.subjects s ON s.id = t.subject_id
WHERE t.status = 'published';
```

Из-за `security_invoker = true` запрос выполняется с правами ученика (`anon`), а у `anon` нет `SELECT` на:
- `classes`
- `subjects`

Поэтому view для детей фактически пустая/недоступная, даже несмотря на то что сам тест опубликован.

---

## Что исправлю

### 1. Пересоздам `public.public_tests` безопасным способом
Уберу зависимость student-flow от закрытых таблиц на уровне прав доступа.

Сделаю так, чтобы `public_tests` оставалась публичной витриной опубликованных тестов, но могла возвращать:
- `id`
- `title`
- `kind`
- `time_per_question_sec`
- `class_id`
- `class_name`
- `class_year`
- `subject_id`
- `subject_name`
- `created_at`

При этом view будет работать для учеников без открытия прямого чтения `classes` и `subjects`.

На практике:
- пересоздам `public.public_tests` без `security_invoker = true`
- оставлю публичным только сам view
- базовые таблицы `classes` и `subjects` не стану открывать для `anon`

Это самый чистый вариант для этой схемы.

### 2. Оставлю фронтенд-фильтрацию как есть
`src/lib/dbTests.ts` уже написан в правильную сторону:
- один запрос к `public_tests`
- никаких запросов к `classes`/`subjects`

Поэтому здесь, скорее всего, нужен только минимальный контрольный просмотр и при необходимости маленькая типизация/логирование, но не переписывание логики заново.

### 3. Сохраню публичность только для нужных данных
Никакие чувствительные поля наружу не уйдут:
- не открою прямой доступ к teacher-данным
- не открою прямой доступ к внутренним таблицам
- у учеников останется только безопасная витрина опубликованных тестов

### 4. Проверю экран выбора теста
После исправления на шаге выбора работы у `9 класс → Технология` должны быть:
- `Итоговая контрольная (3 четверть)`
- `Самостоятельная: Поиск, адресация и логика в Интернете (21.04.2026)`

### 5. Заодно проверю открытие самого гибридного теста
Потому что после появления в списке важно убедиться, что:
- `DbTestRunner` открывается
- вопросы грузятся из `public_test_questions`
- письменная часть и прикрепление файлов видны как задумано

## Что изменится по файлам

### База данных
- новая migration:
  - `DROP VIEW IF EXISTS public.public_tests`
  - `CREATE VIEW public.public_tests AS ... JOIN classes ... JOIN subjects ...`
  - `GRANT SELECT ON public.public_tests TO anon, authenticated`

### Фронтенд
Скорее всего без функциональных изменений, максимум:
- `src/lib/dbTests.ts` — только если потребуется небольшой debug/cleanup
- `src/pages/Index.tsx` — без логических правок, потому что список уже рендерит `dbTests`

Важно: `src/integrations/supabase/types.ts` вручную трогать не буду.
