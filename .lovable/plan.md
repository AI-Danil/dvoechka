

## Live-режим теста: код класса + комната ожидания + общий таймер

### Идея в двух предложениях
Учитель готовит тест и получает короткий **код сессии** (например `7K2P`). Ученики на главной вводят этот код и ФИО, попадают в **комнату ожидания**, а когда учитель жмёт «Старт» — у всех одновременно стартует один и тот же обратный отсчёт. По истечении времени или по кнопке «Стоп» работы автоматически сдаются.

---

### Как это будет выглядеть

**Для ученика (главная):**
1. Большое поле «Введите код класса» + кнопка «Войти»
2. После кода — поле ФИО (2 слова, как сейчас)
3. Дальше один из трёх экранов:
   - ⏳ **Ожидание** — «Тест ещё не начался. Ждите учителя.» + имя теста + имя ученика
   - ⏱ **Идёт тест** — обычный `DbTestRunner`, но с **общим таймером** сверху (одинаковое время для всех)
   - 🔒 **Тест завершён** — «Время вышло, ответы отправлены»

Если ученик подключился позже — он сразу попадает на 2-й экран, но таймер у него тот же, что у всех (например, осталось 12:34, а не полные 40:00).

**Для учителя (новая страница `/teacher/live`):**
1. Список своих опубликованных тестов
2. Кнопка «Создать live-сессию» → выпадает поле «Длительность, мин» (по умолчанию 40)
3. Появляется большой код `7K2P` (показывает на проекторе)
4. Список подключившихся учеников в реальном времени (через Supabase Realtime)
5. Кнопки: **▶ Старт** / **⏹ Стоп досрочно** / **✖ Закрыть сессию**
6. После старта — таймер «осталось 23:11» и live-счётчик сданных работ

---

### Что появится в БД

Одна новая таблица `test_sessions`:

| поле | смысл |
|---|---|
| `id` | uuid |
| `test_id` | какой тест запускаем |
| `teacher_user_id` | автор сессии |
| `code` | короткий код, напр. `7K2P` (уникальный среди активных) |
| `status` | `waiting` / `running` / `finished` |
| `duration_sec` | сколько длится тест |
| `started_at` | момент старта (NULL пока ждём) |
| `ends_at` | `started_at + duration_sec` |
| `created_at` | создание |

И мини-таблица `test_session_participants` (кто подключился):
- `session_id`, `student_name`, `joined_at`, `submitted_at`, `attempt_id`

RLS:
- Учитель управляет только своими сессиями.
- `anon` может **только читать одну сессию по коду** (через RPC-функцию `get_session_by_code(code)`), чтобы не сканировать всю таблицу.
- `anon` может вставлять себя в `participants` только для активной сессии.

---

### Edge-функции

1. **`create-session`** (учитель) — генерирует уникальный 4-символьный код, создаёт запись `waiting`.
2. **`start-session`** (учитель) — ставит `status='running'`, проставляет `started_at` и `ends_at`.
3. **`stop-session`** (учитель) — досрочно `finished`, инициирует автосдачу всех `in_progress` попыток этой сессии.
4. **`join-session`** (ученик) — по `code` + ФИО создаёт `participant` и (если уже идёт) `test_attempt`, возвращает `ends_at` для общего таймера.
5. **Доработка `start-attempt`** — научится принимать `session_id` и брать таймер из сессии, а не из теста.
6. **Доработка `grade-quiz-submission`** — при получении автосдачи по таймауту понимает, что попытка из live-сессии.

---

### Realtime

Через `supabase.realtime` подписки:
- **Ученик** слушает свою `test_sessions` запись → как только `status` стал `running`, экран переключается с ожидания на тест.
- **Учитель** слушает `test_session_participants` → видит подключения и сдачи в реальном времени.

Для этого включу `ALTER PUBLICATION supabase_realtime ADD TABLE` для обеих таблиц.

---

### Общий таймер (главная техническая идея)

Вместо «у каждого свои 40 минут с момента старта» используем **абсолютное время окончания** `ends_at` (timestamp в UTC). На клиенте каждую секунду:
```
remaining = ends_at - now()
```
Тогда не важно, когда ученик подключился и сколько раз перезагружал страницу — все видят одну и ту же оставшуюся минуту. Когда `remaining <= 0` — авто-сабмит.

### Что меняется на главной (`Index.tsx`)

Добавлю в самом верху новый блок-переключатель:
- **«Войти по коду класса»** (новый flow — live)
- **«Обычные тесты»** (текущий flow — каталог + db-тесты)

Они не мешают друг другу: код класса — это явный осознанный вход на live-сессию.

---

### Что НЕ меняется

- Существующие тесты, хардкод-каталог, обычная сдача без сессии — работают как сейчас.
- Анти-чит, прикрепление файлов, Telegram-уведомления — переиспользуются один в один.
- Админка и роли — не трогаю.

---

### План работ по шагам

1. Миграция: `test_sessions`, `test_session_participants`, RLS, realtime publication, RPC `get_session_by_code`.
2. Edge-функции: `create-session`, `start-session`, `stop-session`, `join-session`. Правки в `start-attempt` и `grade-quiz-submission`.
3. Страница учителя `/teacher/live`: создание сессии, показ кода, список участников, кнопки Старт/Стоп.
4. Главная: блок «Войти по коду класса» + экран ожидания + интеграция общего таймера в `DbTestRunner`.
5. Realtime-подписки на обеих сторонах.
6. Проверка end-to-end: учитель создаёт код → 2 ученика заходят → один до старта, один после → таймер у обоих одинаковый → авто-сдача по нулю.

---

### Нюансы, которые учту сразу

- **Опоздавшие**: успевают сдать только то, что осталось по общему таймеру. Это и есть смысл «комнаты».
- **Один ученик — один заход**: повторный вход по тому же ФИО возобновляет ту же попытку, не создаёт новую.
- **Срок жизни кода**: автоматически `finished` через `duration_sec + 5 мин` после старта, даже если учитель забыл закрыть.
- **Коллизии кода**: при генерации проверяю, что среди активных сессий такого кода нет.
- **Анти-чит**: оставляем текущий, плюс в Telegram добавлю «📡 Live-сессия `7K2P`», чтобы понимать контекст.
