## Итоговая контрольная 7 класс — Информатика, 4 четверть

### 1. Создание теста в БД

Через `INSERT` в `tests` и `test_questions`:
- `title`: «Итоговая контрольная. 4 четверть. Алфавитный подход»
- `kind`: `written` (все 8 — расчётные задачи с развёрнутым ответом + возможность прикрепить фото тетради)
- `status`: `published`
- `class_id`: `bb6299d1-…` (7А), `subject_id`: `e938dab2-…` (Информатика)
- `time_per_question_sec`: 300 (для письменной фазы это поле не критично — общий таймер 40 мин)
- `author_user_id`: ваш admin user_id
- 8 строк `test_questions` с `response_kind='written'`, `block_title` по группам (Простые / Средние / Сложные), `points` по уровню (Простые=1, Средние=2, Сложные=3), `position` 0–7, `expected_answer` с краткими ответами (для проверки учителем).

### 2. Экран правил перед началом контрольной

Новый этап **`rules`** в `DbTestRunner.tsx`, появляется **после ввода имени, до `intro`/`written`** — только для тестов с признаком «строгие правила».

Чтобы не трогать схему БД и включить правила точечно для контрольных, добавлю условие: показывать этап `rules`, если `test.title` начинается с «Итоговая контрольная» **или** `test.kind === 'written'` и `points > 1` хотя бы у одного вопроса. (Самый чистый вариант — по префиксу заголовка; универсальный флажок в БД сделаем позже, если попросите.)

Содержимое экрана:
- Заголовок «Правила контрольной работы».
- Текст правил дословно из вашего сообщения:
  > «Копировать из других источников строго запрещено. Вставлять текст в поля для ответов из других источников строго запрещено. Можно прикреплять свои файлы, если выполняете задачи в тетрадях.»
- Чекбокс «Я прочитал(а) и понял(а) правила».
- Кнопка «Принять и начать» — активна только при отмеченном чекбоксе.

При нажатии «Принять»:
- Локально пишем в `cheatLogRef` событие `rules_accepted` с `timestamp`.
- Отправляем то же событие через существующий `log-cheat-event` (он уже есть, принимает любой `event.type`) — попадёт в `test_attempts.cheat_log`.
- Переходим к фазе `written` (или `intro` для квизов, если когда-нибудь применим к ним).

Если ученик не примет правила — кнопка «Начать» не работает, тест не стартует.

### 3. Детектор вставки с фиксацией текста и номера задания

Сейчас `onPaste` в `DbTestRunner.tsx` ловит событие на `document` и пишет просто `paste` без подробностей. Это плохо: учитель видит только факт.

Изменения:
- Перевешиваю обработчик `paste` с `document` на конкретные `<Textarea>` ответов в письменной фазе (и оставляю «глобальный» как fallback для всего остального — он будет писать `paste_outside_field`).
- Каждой `<Textarea>` присваиваю `data-question-pos={q.position}` и `data-question-title={q.block_title || '#'+pos}`.
- На `onPaste` у textarea:
  1. Читаем `e.clipboardData.getData('text/plain')`.
  2. Берём `position` и краткий заголовок из `data-*` атрибутов.
  3. Пишем в `cheatLogRef` событие:
     ```
     { type: 'paste_into_answer',
       timestamp: …,
       details: `Задача ${pos+1}${title?` (${title})`:''}: ${pastedText.slice(0,500)}${pastedText.length>500?'…':''}` }
     ```
  4. Отправляем то же на сервер через `log-cheat-event` (попадёт в `test_attempts.cheat_log` сразу, с дебаунсом не нужен — событий мало).
  5. Шлём Telegram-алёрт через `notify(…)` с тем же текстом (он уже дебаунсится 10 сек).
  6. **Не блокируем вставку** — текст всё равно попадает в поле ответа, как вы и просили («сохраняй ответы ученика»). Автосейв подхватит вставленный текст в `draft_answers` уже через 1.5 сек.

Аналогично — на `<Input>` имени и любых будущих текстовых полях ответа.

### 4. Где в UI это видно учителю

- В реальном времени: Telegram-алёрт «❗ Вставка в Задачу 3 (Средний уровень): "<первые 500 символов>"», имя ученика, тест.
- После сдачи: в `test_results.cheat_log` (копируется из `test_attempts.cheat_log` функцией `grade-quiz-submission`) — учитель видит всю историю в админ-дашборде, где сейчас уже отображается `cheat_log`.
- Сами ответы ученика сохраняются как обычно — мы ничего не блокируем, только фиксируем.
