
План: исправить авто-отправку так, чтобы по истечении времени отправлялись именно последние введённые ответы, а не пустой снимок состояния.

1. Найду и уберу опасный вызов отправки изнутри `setTimeLeft(...)`
- Сейчас авто-отправка стартует прямо внутри updater-функции таймера.
- Это плохое место для side effects: React может вызывать такой код не в тот момент, когда состояние формы уже гарантированно актуально.

2. Введу отдельный механизм “таймер истёк”
- Когда время дошло до нуля, таймер только:
  - остановится,
  - выставит `timeLeft = 0`,
  - пометит, что нужна авто-отправка.
- Отдельный `useEffect` уже после обновления состояния вызовет submit один раз.

3. Переведу сбор данных на “живые” refs, а не только на state в замыкании
- Создам refs для актуальных ответов и важных полей:
  - `blitz8`, `tasks8`, `theory7`, `practice7`, `answers9`
  - вложения
  - `grade`, `subject`, `attempt`, `cleanName`
- Эти refs будут обновляться при каждом изменении.
- И ручная, и автоматическая отправка будут собирать payload из refs, чтобы всегда брать последние данные.

4. Вынесу формирование payload в одно место
- Сделаю одну функцию сборки данных отправки.
- Так ручная кнопка и авто-отправка будут использовать одинаковую логику без расхождений.

5. Добавлю защиту от повторной отправки
- Если таймер сработал, а пользователь уже отправляет работу вручную, второй submit не должен запускаться.
- Проверка будет на уровне ref/флага, а не только через `setSubmitting`, чтобы избежать гонок.

Файл:
- `src/pages/Index.tsx`

Технически:
- Главная причина, скорее всего, не просто “старое замыкание”, а сочетание двух проблем:
  1. submit запускается прямо внутри `setState` callback таймера;
  2. payload собирается из React state, который в момент авто-отправки может быть не тем последним снимком, который пользователь видит на экране.
- Надёжное решение: запускать submit после отдельного сигнала “время вышло” и читать ответы из актуальных refs.
