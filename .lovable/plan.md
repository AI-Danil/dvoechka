## Проблема

В текущей архитектуре во время прохождения квиза прогресс пишется **только в localStorage**. На сервер (`student_drafts.quiz`) ничего не уходит, пока ученик не закончит квиз и не нажмёт «Перейти к части 2». Если посреди квиза вкладка крашнется / разрядится телефон / пропадёт интернет — учитель не увидит ни одного ответа.

Письменная часть уходит на сервер с дебаунсом 5 секунд + beacon на `pagehide`. Это нормально, но не идеально на медленной сети — есть окно потери до 5 секунд.

## Цель

Сделать так, чтобы **каждый ответ на квиз** улетал на сервер сразу (не ждать конец квиза), и сократить окно потери для письменной части.

---

## Изменения

### 1. Quiz.tsx — новый колбэк `onProgress`

Добавить опциональный пропс:
```ts
onProgress?: (snapshot: {
  idx: number;
  answers: number[];        // -1 для ещё не отвеченных
  perQuestion: QuizPerQuestionResult[];
  secondsLeft: number;
}) => void;
```

Вызывать его:
- сразу после ответа на вопрос (или таймаута),
- при монтировании, если был resume из localStorage (чтобы сразу пушнуть восстановленный стейт на сервер).

Тик каждой секунды **не** триггерим — это лишний шум, нам нужны только моменты ответа.

### 2. Index.tsx — серверный сейв квиза по каждому ответу

Сейчас `buildServerPayload()` берёт `quizResults` (есть только после финиша). Меняем:
- Хранить новый стейт `quizDraft` (то, что прислал последний `onProgress`).
- В `buildServerPayload` слать `quiz: quizResults ?? quizDraft` — тогда промежуточные ответы тоже попадут в `student_drafts.quiz`.
- Прокинуть `onProgress` в `<Quiz>` (только для теста с квизом, у нас уже есть `cfg`).
- В обработчике `onProgress` — `setQuizDraft(snap)` + триггер немедленного `sendServerSave(false)` (минуя 5-сек дебаунс), но через **throttle 800мс** на случай быстрых кликов.

### 3. Сократить дебаунс письменной части с 5с до 1.5с

В практике сейчас `setTimeout(..., 5000)`. Снижаем до 1500мс — баланс между нагрузкой и риском потери.
Beacon на `pagehide` остаётся как страховка.

### 4. (Опционально) Видимый индикатор «черновик сохранён»

Маленький `text-xs` в углу: `🟢 Сохранено` / `🟡 Сохраняем…` / `🔴 Офлайн`. Не критично — могу не делать в этом проходе, если хочешь минимальный диф.

## Технические детали

- `quizDraft` shape совместим с `quizResults` (`{ answers, correct, total, perQuestion }`) — легко слить в один payload.
- `student_drafts` уже имеет колонку `quiz jsonb` — миграция не нужна.
- `save-draft` функция уже принимает `quiz` — изменения на бэке не нужны.
- Throttle делаем простым `useRef<number>` + `Date.now()`-сравнением, без новых зависимостей.

## Что НЕ делаем

- Не пишем в `test_attempts.draft_answers` (это отдельный канал для live-сессий учителя — там уже всё работает).
- Не меняем UX квиза (один вопрос, без возврата) — только добавляем серверный сейв «под капотом».

Подтверди — реализую.
