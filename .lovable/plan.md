Нашёл ещё одну более вероятную причину и смог воспроизвести её прямо на GitLab:

- GitLab отдаёт HTML, CSS и JS нормально: скрипты `/assets/index-...js` загружаются с `200`.
- Главная страница открывается, выбор класса/предмета работает.
- После клика по тесту «Самостоятельная от учителя» экран остаётся на `Загрузка теста…`.
- В сети после клика нет запроса к `start-attempt` или `get-test-questions`, значит проблема не в Lovable Cloud/API и не в CORS, а в клиентской логике.

Причина в `src/components/DbTestRunner.tsx`:

```text
attemptId изначально null
questions изначально null
вопросы грузятся только если есть attemptId
но UI сначала проверяет if (!questions) и показывает загрузку
из-за этого экран ввода имени/кнопка Начать вообще не рендерятся
attemptId никогда не создаётся
=> вечная загрузка
```

План исправления:

1. В `src/components/DbTestRunner.tsx` изменить порядок рендера:
   - сначала показывать экран ввода имени (`phase === "intake"`), даже если `questions === null`;
   - загрузочный экран показывать только после создания попытки, когда пользователь уже нажал «Начать» и есть `attemptId`.

2. Убрать зависимость первого экрана от уже загруженных вопросов:
   - вместо точного количества вопросов на intake-экране показывать нейтральный текст вроде `Тест от учителя` / `Квиз` / `Самостоятельная`;
   - точные вопросы всё равно загрузятся после `start-attempt` через защищённую функцию.

3. Добавить обработку ошибки загрузки вопросов:
   - если `get-test-questions` вернул пусто/ошибку, показывать понятную ошибку с кнопкой «Назад», а не бесконечную загрузку.

4. Проверить сценарий на GitLab/preview:
   - открыть 7 класс → Информатика → тест от учителя;
   - увидеть экран имени;
   - нажать «Начать»;
   - убедиться, что идут запросы `start-attempt` и `get-test-questions`, и тест открывается либо показывает понятную ошибку.

Дополнительно возможные проблемы, но они сейчас менее вероятны:

- если открывается именно `/auth`, тогда может быть redirect URL mismatch;
- если не грузится вообще весь сайт, тогда проблема в base path/assets;
- если после «Начать» будет ошибка, тогда смотреть уже ответы `start-attempt` / `get-test-questions`.
