## Задача 2. Миграция с GitHub Pages (блокировки в РФ)

GitHub Pages в РФ периодически режут на уровне DNS/SNI у некоторых провайдеров. У тебя уже есть **3 рабочих зеркала** (см. `docs/DEPLOYMENT.md`): Lovable, Netlify, Cloudflare Pages — все смотрят в одну БД. Этого обычно достаточно.

Если хочешь именно «git-хостинг + статика» вместо GitHub:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **GitLab Pages** (gitlab.com) | Доступен в РФ без VPN, есть CI/CD, бесплатно | Нужно зеркалить репо (GitHub → GitLab mirror, авто-пуш). Поддомен `*.gitlab.io` иногда тоже трогают. |
| **Vercel** | Лучший CDN, мгновенные превью, SPA-fallback из коробки | Доступ к dashboard из РФ только через VPN, но сам сайт открывается. |
| **Cloudflare Pages** (уже есть) | Лучший аптайм в РФ из перечисленных | — |
| **Beget / Timeweb / Selectel S3+CDN** | Российские, не блокируются | Нет авто-деплоя из git, нужно настраивать GitHub Actions → rsync/S3. |
| **Свой VPS + nginx** | Полный контроль, любой домен `.ru` | Ручная настройка, обновления, SSL. |

**Рекомендация:** оставить GitHub как source of truth, добавить **GitLab mirror + GitLab Pages** как 4-е зеркало (15 минут настройки), плюс продолжать раздавать ученикам ссылку на Netlify/Cloudflare. Если нужно «совсем без западных хостингов» — Timeweb Cloud Apps + GitHub Actions на push.

Скажи, какой вариант делаем — пропишу в `docs/DEPLOYMENT.md` и заведу workflow.
